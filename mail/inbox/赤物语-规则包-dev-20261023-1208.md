<NumberedList id="h7TLeK55ftmsURSnolflaj">
  <Mark bold>`libs/dev` 只能放纯代码/纯资源模组，不能放 sodium / iris 这类优化模组</Mark>：它们把 `method_XXXX` / `class_XXXX`（intermediary 名）<Mark bold>硬编码在 `@Inject(method=…)` 里且不带 refmap</Mark>，而 dev 环境是 yarn 命名的；loom 的 remap 只重写 refmap、改不动注解字符串 ⇒ 启动即 `MixinApplyError`（`BufferBuilder.method_23918` / `Identifier.method_20208`）。`modRuntimeOnly` / `modLocalRuntime` / `modImplementation files()` 三种写法全崩，<Mark bold>不是配置问题，是这类 jar 在 dev 里根本不能用</Mark>。判据：日志出现 `No refMap loaded` + 目标是 `method_\d+` ⇒ 直接移出 dev 运行时（本工程放 `libs/dev/_disabled/`）。
</NumberedList>

<NumberedList id="ZXXa4wkV1tHNlhBGc8RFF7">
  <Mark bold>`compileJava` UP-TO-DATE ≠ 依赖没变</Mark>：Gradle 对 classpath 做 ABI 归一化，只改依赖版本而源码不引用其类时任务会跳过。要证明「新依赖真进了编译类路径」，必须写一个<Mark bold>临时引用其类的探针文件</Mark>编一次，再删掉重编（删完要确认 `build/` 与产物 jar 里 0 残留）。
</NumberedList>

    同族（1 次，B 第 32 轮）：<Mark bold>按「格子」存附属数据时要覆盖两个 `removeStack` 重载</Mark>。`weights[slot]` 只清 `applyClearSlot`，而「把物品拖回背包」走 `Slot.onTakeItem ⇒ Inventory.removeStack(slot, n)` ⇒ 新物品<Mark bold>静默继承</Mark>上一件的权重（权重 50 的钻石换成苹果，苹果直接占 50/51 概率）；且 `SimpleInventory.removeStack(slot)` <Mark bold>不经过</Mark> `removeStack(slot, n)`，两个都要覆盖。
  </BulletedList>

  <BulletedList id="pq6ItjXToCZGvLyDwrS9Ad">
    同族（1 次，B 第 21 轮）：`setNbt(data.toNbt())` 是<Mark bold>整包覆盖</Mark> ⇒ 铁砧改名 / lore / RepairCost 全没，写回必须以现有 tag 为底只覆盖自己拥有的键（细节见流水账 2026-10-22 B 第 21 轮条）。
  </BulletedList>
</NumberedList>

<NumberedList id="FPgO0IEqWRz1RcFT16Guir">
  <Mark bold>「倍率 × 钱」一律整数或 `floor(x + 1e-6)`，double 直接 floor 会每件少收 1 铜（2 处同轮实证：A 第 N+61 轮）</Mark>：`100 * 1.15 == 114.99999999999999` ⇒ `(long) Math.floor(price * m)` 按 114 收；`100 * 0.29 == 28.999999999999996` ⇒ 卖价少 1 铜。实测两处：`GuildModule.applyShopDiscount`（重度加税 15%）、`ShopCatalog.sellPrice`。对照 `ShopTax` 用整数 `(price * pct + 99) / 100` 天生没这问题 ⇒ <Mark bold>能用整数就别用 double</Mark>；必须用 double 时统一 `floor(x + 1e-6)`，且 `applyShopDiscount` 的短路条件不能写 `m >= 1.0`（会把「加价」直接 return 掉，见流水账 A 2026-10-22「静默吃掉加价」条）。
</NumberedList>

<NumberedList id="X4CYn8IOFJSOqxe99CqwOQ">
  <Mark bold>同一动作 / 同一状态只要有两个入口或两份真值，必有一份没守住规则（≥8 次：R70b/R101/R114/R67/R50/R51/R57/R61）</Mark>：`/pay` 走全套校验、`PayNetworking` 又写一遍 ⇒ 界面路径绕开全部校验、还能对离线玩家报「找不到在线玩家」；`weights[]` 按格子存却只覆盖 `removeStack` 两个重载 ⇒ shift-click 移出后新物品继承旧权重（清空容器有 `setStack`/`removeStack(2 个)`/`clear()`/`quickMove` <Mark bold>五个</Mark>入口）；取色只改 `scanAndPlan` ⇒ `Probe`/`Preflight` 两个调用点照旧传 null world；切页「点侧栏」与「深链」两套 switch ⇒ 深链进来空页；滚动上限在滚轮/渲染/命中各写一份 ⇒ 下滑后点错格。判据三条：① 渲染画控件用的 `x/y/w/h` 必须<Mark bold>原样</Mark>进命中（抽 `canAct()` 同时喂 render 与 click）；② 一个状态被画成不可用 ⇒ 必须有<Mark bold>一个纯函数</Mark>同时决定「画不画灰」与「点不点得动」；③ 出现「同一段 if / 同一常量」在两个文件里 = 两条实现，改完必须 grep 旧遍历点确认只剩一处。
</NumberedList>

<NumberedList id="kRtgpydSlYEP9sgTFGaBfN">
  <Mark bold>夹具/探针开跑前先自证三件事：跑的是谁、等的什么信号、拍的是哪一帧（≥10 次：R64/R65/R77/R81/R89/R94/R95/R99/R100/R116）</Mark>：`runClient` 不带 `--quickPlaySingleplayer` 停在标题界面（`mc.world==null`，一张图都不出）；`--single` 只改任务名不改 `--root` ⇒ 「1.20.1 复验」实际起的是 1.21.1 服务端还空等 300 秒；就绪标记挂在被本局配置关掉的代码路径上（`sampled=` 只在 `dryRun=false` 时打）⇒ 空等满 600s 且 rc=0 假绿；`run/*.flag` 两套夹具互抢 ⇒ 客户端 20 秒自杀、0 张图。定式：① 判「这局跑的是谁」<Mark bold>只认日志首行 `Loading Minecraft <ver> with <Loader>`</Mark>，不看任务名/文件名/mtime；② 就绪信号必须<Mark bold>在任何配置档下都会出现</Mark>（`「这个信号在任何一档配置下都一定出现吗？」` 不成立就换）；③ 证据要能区分旧图/旧日志/旧 jar（映射带 `log_mtime`、jar 用 `javap -c` 证明这轮的调用进了包，不用 mtime）；④ 几何/常量一律<Mark bold>反射生产侧</Mark>（夹具日志打 `GEOM`），不在 Python 里抄一份；⑤ 收尾按 #35 的清单核。
</NumberedList>

<NumberedList id="JOEHfMtJAVTpp2yBePcy09">
  <Mark bold>诊断数字本身要先可信：计数器写在 `catch` 之前，分母从源码现数（2 次：R108 / R113）</Mark>：`for(...){try{...}catch(Throwable){continue;} p.total++;}` 全抛时 `total=0` ⇒ 日志「注册表 0 方块」把根因方向带偏一整轮；`fail / 7` 写死而实际 9 条 ⇒ 前 7 条过就打印「7/7」，新加的两条<Mark bold>永远不会被看见</Mark>。定式：① `iterated++` 放 try <Mark bold>之前</Mark>、`ok++` 放之后，两者不等就是「被吞了多少」；② 静默 `catch` 必须留 `caught` + `firstError(id)` + `firstTrace(前 8 帧)`，否则根因只能猜；③ 分母只在<Mark bold>一处</Mark>出现且从源码条数现数，门内断言「分母 == 断言条数」。
</NumberedList>
