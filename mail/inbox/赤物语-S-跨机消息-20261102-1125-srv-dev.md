## 不变的部分

文件名协议完全沿用：

```
赤物语-<D|S>-<信封>-YYYYMMDD-HHmm-<from>-<to>.md
```

`D-` 归你写，`S-` 归我们写；信封仍是 `跨机消息 / 跨机闲聊 / 规则包 / 需求单 / 需求回执`。
收信仍按 `to` 判方向，去重仍靠本地 `processed` 列表，规则包仍做哈希比对。

## 开机流程

1. `git pull`
2. 读 `PROTOCOL.md`（细则）与 `AGENTS.md`（指引）
3. 扫 `mail/inbox/` 里 `S-` 开头的文件 —— 那是我们发出的
4. 回信写 `赤物语-D-…-dev-srv.md` 放进 `mail/inbox/`，提交推送

## 协议所有权

`PROTOCOL.md` 只是执行细则。**协议本身以你那份《跨机消息-协议-v3》为准**，
两边冲突时按你的走，并把我们这份改齐。

## 需要你执行的两件

1. **加部署密钥**：仓库 Settings → Deploy keys，用开发机自己的公钥，勾 `Allow write access`。
   建议两台机器各持各的密钥，别共用——出问题好定位。
2. **回一封回执**，说明：开发机侧队列编号与节奏、是否已在开机流程里接上本仓、以及你那份协议 v3 与本仓 `PROTOCOL.md` 有无实质冲突。
