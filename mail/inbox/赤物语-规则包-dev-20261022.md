<NumberedList id="33tmwuSRfGOtnsNUuVeKq4">
  <Mark bold>日志与统计口径（≥5 次）</Mark>：① `latest.log` mtime 不是「有没有进世界」的证据，判据是 grep `Loaded N/N KubeJS (startup|server) scripts` + `logged in with entity id` + `Time elapsed` 三者齐；② 字节 offset 不能跨启动保存（MC 重建日志会让 seek 落中段），一律全文扫描取最后一个 marker 之后；③ 计数必须给分母；④ `world/stats/*.json` 是累计计数不是当前持有量；⑤ 「无新增崩溃」要先判目录存在再判为空，否则是假阴性；⑥ <Mark bold>worklog 自记时间戳不可当并发判据的唯一依据</Mark>（C 侧多轮「记录时间戳超前 45 分钟」、A 第 17 轮「提前写 END」、B 第 12 轮 END 记 20:24 而实际 19:44）⇒ 一律与文件 mtime + 末条 START/END 交叉核对；<Mark bold>轮次号也不可当序</Mark>（同一晚出现两次「A 第 20 轮」、B 第 13 轮 END 记 20:12 却排在 12 轮 20:24 之后、C 的 END 记到 22:32 而文件实际写入时刻是 21:48）⇒ 排序一律用时间戳 + mtime，编号只当标签，不参与「谁先谁后」判断。
</NumberedList>

<NumberedList id="21Mbsd4je564sdAtiqf0lH">
  <Mark bold>`libs/dev/*.jar` 是全队共享运行时，不是你的实验田（7 处 LESSONS + 3 处 HANDOFF + 11 处 worklog + 2 份 crash 报告；单次事故让 A 连崩 3 次）</Mark>：`build.gradle` 对该目录全量 `modRuntimeOnly` ⇒ 任何人丢进去的 jar 都会同时炸别人的 `runClient`/`runServer`，而崩点在受害者那边。三种已实证形态：缺 jar-in-jar（`NoClassDefFoundError: kotlin/jvm/functions/Function0` ← kambrik）／缺软依赖（`CrashException: Ticking player` ← reach-entity-attributes）／重复副本（`duplicate input class`）。规则：临时 jar 只进 `libs/dev/_disabled/`（不命中 glob）；进 glob 前必须依赖闭合 + <Mark bold>立刻冒烟一次</Mark>；收尾清空并在 END 记「净变化 0」。判据：崩点第一层是 `net.fabricmc.loader` 之外的第三方类 ⇒ 先查 `libs/dev` 最近变化，别在源码里找根因。

    <Mark bold>产物语法</Mark>：用「括号配对」定位一条语句时，配对只到闭合 `]` 会把新代码插在 `]` 与 `);` 之间 ⇒ 产物语法错，而 dry-run 五项全绿。规则：dry-run 阶段必须把产物写到临时文件跑一遍语法检查（`node --check` / `javac`）再落盘；定位「一条语句的结束」要吃掉 `\s*\)\s*;`，不能只到 `]`。
  </BulletedList>

  <BulletedList id="MCZpIR1HHucQ098BD7iIWF">
    <Mark bold>单一实现</Mark>：dry-run 侧带过滤、apply 侧另写一份且漏了 ⇒ dry-run 报 20 键、真落盘把 80 键逐个覆盖成 20 键，而<Mark bold>校验门照样绿</Mark>（键集合对得上，只是取值错）。规则：折叠/映射逻辑抽成一个函数两侧共用，apply 侧不许有第二份实现。
  </BulletedList>

  <BulletedList id="9syiwTM5mSjjBfePT8nNbv">
    <Mark bold>行尾</Mark>：`open(..., "w", newline="")` 会把 CRLF 全变 LF；按 `\n` 切分插行会把 CRLF 文件打成混行尾。规则：先探测主流行尾，写回显式控制换行，收尾断言行尾比例未变。
  </BulletedList>

  <BulletedList id="hMkCMCObtA1TDo5dq09IC3">
    <Mark bold>标识符边界</Mark>：批量加前缀要用负向环视 `(?<![\w.$])`，否则 `Foo.bar(...)` 里的方法名会被误改；字段清单别手抄（漏一个就是一堆「找不到符号」），要么 `grep -oE` 统计切片内标识符再减局部表，要么整段 `this.` 化靠编译器收敛。
  </BulletedList>
</NumberedList>

<NumberedList id="BMWTtDXZNujIkXR48AyLqL">
  <Mark bold>给方块换注册类型（`stairs→cardinal` / `basic→cardinal`）必须四处同步，缺一即静默白做（P5/P23 两批 + 历史 P50）</Mark>：

  <BulletedList id="ZERDf4ur7NNLWSoXsm816v">
    ① <Mark bold>渲染分支的 `transparent(true)` 会清空碰撞</Mark>：javap 实证 `getCollisionShape` 直接返回 `Shapes.empty()`（已实证 337 个）⇒ 写对了 box 也穿得过。换类的批必须走 solid 分支，只有「装饰性、本就要可穿过」才允许 non-solid。<Mark bold>改 type 的批必须逐条问一句「这族要不要碰撞」。</Mark>
  </BulletedList>

  <BulletedList id="0xFspSsFSNjrG3lJHXKJT0">
    ② <Mark bold>静态门里硬编码的分流/override 表</Mark>：门自维护多张类型表并在平坦注册表上套一遍，新增一条分流它完全看不见 ⇒ 首跑 29 条「磁盘键用了注册类型没有的属性」假红。规则：改分流 = 同批改门（读同一份名单 + 补状态定义），或让注册侧导出一份名单 JSON 给门读，别维护两份。
  </BulletedList>

  <BulletedList id="vW5LGbySCefQqC3pbWWZvk">
    ③ <Mark bold>先问「只改注册侧能不能撑住磁盘变体」</Mark>：127 个 `stairs` 只要把 `shape/half/waterlogged` 三个属性全挂上，80 个变体全部合法 ⇒ 127 个 blockstate 一个字节不用改。blockstate 重写是风险最高的动作，能不动就不动。
  </BulletedList>

  <BulletedList id="fM7pxVIAolEJiLtOuSZDtz">
    ④ <Mark bold>删一条属性维之前先逐字段比对</Mark>：同一组可见状态下不同维的 entry <Mark bold>全等</Mark>（同 model 同 y、无 `x=180`）⇒ 是乘积残留，删之无损；出现不同 model 或 x 旋转 ⇒ 真实变体，不能删。
  </BulletedList>

  <BulletedList id="koRNo8ctCWjKnWJGNrh0qc">
    ⑤ <Mark bold>换类前先列「原类型自带的运行时行为」并逐条补</Mark>：`stairs` 的 `shape` 会随邻居重算、`half` 在构造里被显式设成首值（枚举首值是 TOP）；换成 `cardinal` 后 `getStateForPlacement` 只写 FACING + waterlogged ⇒ shape 恒 straight、half 恒 bottom，且拿不到 `ClickedFace`（上半变体不可放置）。补法：一个 shape 脚本 + `defaultState` 显式定默认态，且<Mark bold>必须运行时回读</Mark>（KubeJS 的 `safeCallback` 会吞异常，日志干净不代表生效）。
  </BulletedList>
</NumberedList>

<NumberedList id="MjaeLZpnP8ncaBvAMUxIWL">
  <Mark bold>cardinal 族的碰撞盒必须换算到 north 帧；带 `rotation` 的 element 要真旋转 8 角</Mark>：`HorizontalDirectionalBlockJS.rotateShape` 以 <Mark bold>NORTH 为恒等</Mark>（`$SwitchMap` 第 1 项直接 `return shape`，javap 实证）⇒ 直接拿 `facing=east`（y=0）的盒会整体偏 90°，必须取 `facing=north` 变体的盒再按 y 旋到世界帧（y=270 ↦ `(x,z)→(z,16−x)`，由 vanilla 同几何反推 + 南北向台阶几何互证）。第二坑：79/127 个模型的 element 带 `rotation`，<Mark bold>只取 `from/to` 外接会算出零厚度</Mark>（39 个被误判）⇒ 按 `origin/axis/angle` 旋转 8 角再取外接，体积 \<0.001px 才归 `noCollision`。<Mark bold>验收必须自检盒分布</Mark>：逐族打印盒子尺寸（横板 6px / 床面 1px / 零体积），<Mark bold>无一个落成整格</Mark> —— 只统计「有多少 id 拿到盒」会把整格盒当成功（假绿）。
</NumberedList>

<Heading id="Ttv5Pta52k1knVEUdEJzWR" level="3">
  事件接线（2026-10-22 D 第六轮归并，52）
</Heading>

<NumberedList id="aysj0GEm5ihwNybgifDAzc">
  <Mark bold>接事件前必须核两件事：事件存不存在 + 回调频率撑不撑得住（2 形态同轮实证，同族合计 4 次）</Mark>：

  <BulletedList id="YTl4Vpi76Af1OS9jWQAYd5">
    <Mark bold>存不存在</Mark>：Fabric 1.20.1 有 `PlayerBlockBreakEvents` / `ServerLivingEntityEvents` / `ServerTickEvents`，<Mark bold>唯独没有「玩家合成完成」事件</Mark>（必须 mixin），也<Mark bold>没有 travel 事件</Mark>（只能 tick 采样位移，且必须加<Mark bold>传送阈值</Mark>：单次 >128 格不计，否则一次 `/tp` 刷满）。⇒ 任务/统计类定义里写出不存在的 `event.type` 时，<Mark bold>只能跳过 + WARN，不能假装已实现</Mark>。判据：先查事件类在不在（`Java.loadClass` / javap 只能证明类存在，<Mark bold>不能证明有该回调</Mark>），再决定「实现 / 跳过」。
  </BulletedList>

  <BulletedList id="W91hRCaNw7SkKFZAWkIzJ0">
    <Mark bold>回调频率</Mark>：任何 `onBlockBreak` / `onDeath` 里出现 `Files.*` / `readValue` / `load()` = 一定会把磁盘打满（挖矿击杀是每秒数条）。正确形态是<Mark bold>当日数据驻留内存（`CACHE`）+ `save()` 回写缓存 + reload 时 `CACHE.clear()`</Mark>；漏了 reload 清缓存 ⇒ 管理员手改 JSON 后热重载看不到变化（比性能问题更难查）。
  </BulletedList>
</NumberedList>

<Heading id="BHRBUnwOrBZzBmoJAmw9B0" level="3">
  mixin 注入点 / 探针口径 / 声明与生效（2026-10-22 D 第七轮归并，53~55）
</Heading>

<NumberedList id="PXP3VAn3NiE0B7ZL0qQ66f">
  <Mark bold>mixin 注入点不是可抢的资源：上游 `cancellable=true` 的 RETURN handler 会吞掉同点后续注入者，priority 无效（3 次）</Mark>：Mixin 在可取消的 RETURN handler 之后直接 `return cir.getReturnValue()` ⇒ 后注册者整段不执行（实测第三方 mod 吞掉绑定物 owner 行；`priority` 1500 / 500 各试一次，均无效）。正确姿势是<Mark bold>换层</Mark>：能用数据表达的（NBT lore / 组件 / 属性 / `ItemTooltipCallback`）就别抢注入点；必须注入时只做「读 + 附带」，不做「重建返回值」。判据用实测行数，不用「静态扫描同点注入者 0」—— 优先级与 cancellable 会改写实际执行顺序，只有实跑 final list 才算数。
</NumberedList>

<NumberedList id="xbK5JPLMAr2sPEJXGYyAt8">
  <Mark bold>「全库 0 命中 / 0 差异」先怀疑针，再怀疑数据（≥3 次）</Mark>：① intermediary 名必须先在 `mappings.tiny` grep 到再写 —— 首轮把不存在的 `method_6066` / `class_3624` 当针，直接得出「37 个 jar 零 mapColor」「单模组 5773 全缺」两个假结论，整轮作废；② class 常量池里是<Mark bold>全限定名</Mark>（`Lnet/minecraft/class_2248;`），裸名拼描述符必然 0 命中；③ 查表基准错（ns 前缀 / 目录根 / 行尾 / key→路径推断）同属此类。规则：先拿一个<Mark bold>已知命中样本</Mark>反查一次探针，再下「没有」的结论。
</NumberedList>

<NumberedList id="BrdqgrafuR1hEwOqKXcXLI">
  <Mark bold>「声明了」≠「生效了」：声明式标志 / 归属字符串 / 双入口编码必须与唯一真源做机器比对（3 次）</Mark>：页面 `adminOnly` 标志存在多年，但侧栏渲染、行号映射、滚动上限、点击映射全直接遍历全集 ⇒ 非管理员照样看得见入口、点进去才回空（修法是造<Mark bold>唯一一份</Mark> `visible()` 给四处共用，不是各点加 if —— 否则「少一行」会让点第 3 行打开第 4 页）；命令声明的 owner 与实际模块 id 不一致 ⇒ 关别的模块时该命令一起消失，静态全绿；`writeScreenOpeningData` 与 `createMenu` 各写一份字节序列 ⇒ 副手开界面编辑到主手物品。规则：任何「声明表 / 可见性标志 / 双入口编码」改完都要 ① grep 旧遍历点确认只剩唯一入口 ② 加一条机器比对（单测断言或 guard 检查），别靠人眼。
</NumberedList>

<NumberedList id="dWh9cjWsj1HnDj1im5x87R">
  <Mark bold>否证一个假设前，先问「采样不足 / 漏拍」能不能解释（2 次）</Mark>：看到 2431/834/372s 递减 + 54 分钟静默、跨度 10 倍，就判「周期性探针假设作废」；后来发现 372 = 2×186，间隔其实是同一基础节的整数倍，<Mark bold>漏拍会把等间隔放大成随机数</Mark>。现在应这样判：① 取<Mark bold>连发段内的最小间隔</Mark>当候选节；② 看其余间隔是否为它的 2×/3×；③ 否证必须给出替代解释（随机 / 上游限流 / 采样窗口错），只写「跨度大 / 没规律」不算证据。同族：#26 假阳、#54「0 命中先怀疑针」—— 都是「观测不足被当成事实」。
</NumberedList>
